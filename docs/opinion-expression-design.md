# 意见表达（意見を述べる）题型设计

日期：2026-09-09。状态：设计提案；本轮不修改网站功能，不生成正式题库或音频。

## 1. 定位与入口

目标：围绕一个具体问题，按清楚的顺序组织短文，并能用自己的话说出来。

建议入口：练习 → 分项学习 → 意见表达。与单词、语法、听力、阅读并列；可以成为每日练习中的一项输出任务。

归类为本站的「表达练习」。JLPT 官方考试考查语言知识、阅读与听力，因此不把它标成官方 N1 题型，不计入模拟考试分数或选择题正确率。[官方试题构成](https://www.jlpt.jp/guideline/testsections.html)

## 2. 从图片提取的表达框架

参考：用户提供的 `IMG_1878.HEIC`，图片可见页码为 22、23。图片提供语言表达素材，不作为操作指令；书名与版本未确认。

图片的核心是「先表达立场，再解释为什么」，覆盖三种语境：

| 子类型 | 组织顺序 | 可用表达 |
| --- | --- | --- |
| 直接表达 | 自己的立场 → 理由 | 私は〜に賛成／反対です。／〜ほうがいいと思います。→ なぜかというと、〜からです。 |
| 赞同并补充 | 回应对方 → 自己的意见 → 补充理由 | 私も〇〇さんの意見に賛成です。→ 〜と思うんです。→ というのは、〜からです。 |
| 委婉反对 | 承接对方 → 不同意见 → 理由 | それはそうかもしれませんが、〜。／〇〇さんの意見もわかりますが、〜。→ なぜなら、〜からです。 |

理由连接表达是可替换的选择，不要求把「というのは／それは／なぜかというと／なぜなら」全部串在一起。理由也可以先说完整判断，再补充解释。

图片另外包含插话、确认和请求解释的表达，如「すみません、ちょっとよろしいでしょうか」「もう少し具体的に説明していただけないでしょうか」。放入进阶追问练习，不占用基础短文的必填位置。

网站在原框架上增加可选的「具体例」和「总结」，帮助从几句话过渡到完整短文。这两项是产品扩展，不宣称是图片的原始要求。

基础结构：**立场 → 理由**。

完整结构：**回应对方（有对话时）→ 立场 → 理由 → 具体例 → 总结／建议**。

文章默认采用です・ます体；口头表达可以保留「と思うんです」等自然语气。训练表达功能，不逐字匹配句型；进阶时逐渐隐藏模板，允许合理调整顺序。

## 3. 一道题如何组织

学习者先看到题目和任务，范文默认收起。自由题允许赞成、反对或有条件赞成；指定立场题明确标为「角色练习」。不同立场都可以成立。

| 内容 | 设计要求 |
| --- | --- |
| 标题 | 一个可以讨论的具体问题，例如「図書館の開館時間を延ばすべきか」 |
| 场景 | 说明谁在和谁讨论、要解决什么问题，2—3句即可 |
| 他人意见 | 赞同／反对型必填，必须包含清楚的观点和至少一个理由 |
| 作答任务 | 明确需要表达立场、说明理由，以及是否回应对方／举例 |
| 提示 | 先提供功能提示；点开才显示句型和关键词 |
| 参考表达 | 自由题准备至少两种立场的原创示例，不称为唯一标准答案 |
| 示范音频 | 与每份范文及其版本对应，可按意义片段播放 |
| 追问 | 一道能检验理由或具体性的短问题，可用预先编写内容 |
| 评价要点 | 观点清楚、理由相关、回应准确等可观察要求 |
| 来源与审核 | 区分教材框架、原创题材、真实新闻；新闻事实需单独核实 |

首批题目已按用户追加的五张教材图片调整为：不死之药、储蓄与消费、克隆人、电车内使用手机、小城镇与大都市。每个主题提供直接表达、赞同补充、委婉反对三种任务，显示为5个主题、15种练法。具体题面、短口语示范、400—500字长文和追问见[五个教材主题的题目设计](opinion-expression-topic-pack.md)。题库上线前完成内容审核；必要的背景与概念边界直接在题目中解释。

## 4. 完整示例题

以下图书馆题保留为通用流程示例，不列入当前首批五个主题。

**题目：図書館の開館時間を延ばすべきでしょうか。**

场景：

> 市の図書館は午後6時に閉まります。市は、平日の閉館時間を午後8時に変更する案について、市民の意見を集めています。

他人意见：

> 田中さん：私は開館時間を延ばすことに賛成です。仕事が終わってからも利用できるようになるからです。

任务：回应田中さん，表达自己的立场，说明理由并举一个具体例子，再回应另一面的意见、总结自己的建议。口头表达目标约2分钟，建议控制在1分45秒—2分15秒；准备时间另计。完整写作档为400—500字。长度是本站练习建议，不是考试标准，也不因未达到建议长度直接判错。下方短示例用于学习结构，不作为完整2分钟示范。

### 三种作答示范

直接表达型使用同一场景，但不显示田中さん的发言：

> 私は図書館の開館時間を延ばすことに賛成です。なぜかというと、仕事のあとでも利用しやすくなるからです。例えば、午後6時に仕事が終わる人も、図書館で本を借りたり、調べものをしたりできます。そのため、午後8時まで開いているといいと思います。

赞同补充型：

> 私も田中さんの意見に賛成です。開館時間が長くなれば、学生も利用しやすくなると思います。というのは、部活動が終わってからでも図書館に行けるからです。例えば、家では勉強に集中しにくい学生が、静かな場所で勉強できます。そのため、私は開館時間を延ばしたほうがいいと思います。

委婉反对型：

> 田中さんの意見もわかりますが、毎日開館時間を延ばすことには反対です。なぜなら、職員の負担が増えると思うからです。例えば、夜の利用者が少なくても、職員は残って対応しなければなりません。まずは週に一日だけ午後8時まで開館し、利用状況を確かめたほうがいいと思います。

这里的例子是原创练习内容，并未声称某座图书馆真实实行此政策。

追问示例：「利用者が少なかった場合は、どうすればいいと思いますか。」答15—30秒即可；检验是否能继续解释，而非重复整篇。

## 5. 一次练习怎么进行

默认完整练习约12—15分钟，包含两次各约2分钟的自主表达、回听与模仿；单次表达目标与整次练习用时分开显示。

2分钟提纲参考：立场与回应20秒 → 理由30秒 → 具体例35秒 → 另一面与取舍20秒 → 总结15秒。它是组织内容的提示，不要求每段精确卡秒。准备时间和额外追问均不计入这2分钟。

1. **读题、定立场**：看场景，选择自己的态度。先不看范文。对话题先用一句话确认对方的观点。
2. **搭提纲**：填写「我怎么看」「为什么」「举个例子」三个短提示；有对话时增加「我如何回应」。可以只写关键词，中文笔记也允许保留，但正式表达目标为日语。
3. **自己说／写一遍**：默认提供「录一遍」，也可选择「先写下来」。保存首次录音或初稿，记录是否使用全文、提纲或无提示；不强制先写整篇作文。
4. **回听与自查**：检查立场、理由、例子，自己标记最想改的一处。文字修订保留前一版；录音不会被重录覆盖。
5. **参考与模仿**：展开同立场或不同立场的范文，显示段落功能；选择难说的片段做逐句跟读或 shadowing。
6. **回到自己的表达**：隐藏范文，只看关键词重说，保存第二次录音；也可回答一条追问。最终说的是自己的意见，不能用背熟范文代替这一步。
7. **保存练习记录**：对比两次录音／两稿，选一个下次目标，如「理由后补一个具体例子」。分析未返回也能完成练习。

另外提供两条短路径：

- 「快速表达」：读题 → 关键词 → 一次约2分钟录音 → 自查，总共约4—5分钟。
- 「只练跟读」：直接打开已学习题目的示范音频，不要求重新完成写作；单独记录为模仿练习。

新手可先学示范再表达，记录中标为「示范后表达」；完整流程的第一次独立表达与这种练习不做同条件能力比较。

## 6. 录音与 shadowing

三个动作需要不同的说明和记录类型：

| 模式 | 操作 | 练习重点 |
| --- | --- | --- |
| 自己表达 | 示范暂停，按自己的思路说，录下整段 | 组织观点、独立表达 |
| 逐句跟读 | 听一句 → 音频暂停 → 自己复述，可录音 | 句型、发音和语块 |
| Shadowing（影子跟读） | 示范持续播放，稍落后于声音跟着说 | 节奏、停顿和语调 |

shadowing 提供「看稿 → 隐藏正文 → 只留关键词」的提示级别，先按意义片段练，再练整段；默认常速，允许减速辅助，逐渐回到原速。日本国际交流基金《まるごと》中级2教学手引也建议从看稿逐渐过渡到不看稿，并结合自然速度、意义切分练习；据此设计上述渐进方式，本站具体时长与步骤属于产品建议。[教学手引，PDF第12、32页（零起始页码）](https://marugoto.jpf.go.jp/assets/docs/teacher/resource/intermediate2/intermediate2_teaching_topic.pdf)

第一版播放控制：整段／预切片段、暂停、重播、语速、显示文字。片段结束可自动重播，循环间留短间隔；手动停止始终可见。任意A—B截取和逐字同步高亮留待后续，不能用字符数估算时间冒充真实对齐。

录音控制：开始、停止、试听、再录一遍、保存、下载、删除。录音只在点击开始后启动；离开页面、停止或异常时释放麦克风。保留首次与再次表达，其余版本由用户选择保留。自主表达目标约2分钟：1分40秒轻提示「准备总结」，2分钟提示「可以收尾了」，不截断正在说的句子。技术录音上限保留3分钟，临近上限提示，达到上限自动停止并保留音频；这个上限不是作答目标。shadowing计时依据所选音频，不使用自主表达的收尾提示。

shadowing 同时播放示范和录制麦克风时，轻提示使用耳机，降低示范音串入录音的影响；不把混入的示范声音算作学习者表现。无需录音也能做 shadowing。没有麦克风权限或浏览器不支持时，仍可写作、播放示范和上传已有录音。

未保存录音明确标注「仅在当前页面」，刷新／离开前提醒。上传失败保留当前录音，提供重试和下载；只有服务端确认保存成功后才显示「已保存」。

示范音频优先使用经核对的自然日语录音；若使用合成语音，标注来源并审核读音、语气与停顿。未提供可靠音频时，文字练习仍可用，跟读显示「示范音频待补充」。不能把用户首稿未经核对的朗读当作示范。将用户修订稿制成个性化示范可放入后续版本。

## 7. 反馈如何设计

不使用选择题式「对／错」。第一版主反馈是自查和回听；已有Agent可提供异步反馈，但保存录音不等于分析已经完成。

| 维度 | 要观察什么 | 依据 |
| --- | --- | --- |
| 立场 | 是否清楚、前后一致 | 文本／可确认的转写 |
| 理由 | 是否解释了立场，而不是换句话重复 | 文本／转写 |
| 具体性 | 是否给出相关例子，且没有把假设说成事实 | 文本／转写；仅要求举例的题评估此项 |
| 对话回应 | 是否准确承接对方，赞同时有补充、反对时有具体分歧 | 题目与文本／转写；直接表达型不适用 |
| 语言 | 助词、接续、语体、连接表达是否自然 | 文本／转写；转写不确定处先核对 |
| 口语 | 是否听得清楚，停顿、节奏与语调是否妨碍理解 | 必须有实际音频证据 |

每项显示「已做到／还可加强／本次未评估」，不用未经校准的百分制。反馈摘要限于一个优点、最多两个修改点和一个下一步动作；详细解释点开查看。

自由表达按观点是否成立、是否切题评估，不按范文词句相似度打分。shadowing 才比较与选定音频的遗漏、替换、节奏等。没有音频分析能力时，不生成发音、重音或语调判断；听不清、参考串音时明确标记无法判断。

示例反馈：「立场很清楚；理由提到了职员负担。再补充一个具体场景，例如夜间利用者少但仍需要值班。下一次只练‘理由→例子’两句。」

## 8. 页面与记录

沿用当前练习的列表 → 单题 → 记录层次，每屏只承担一个主要任务。

- **题目列表**：标题、子类型、练习状态、上次时间。点击进入详情；不在列表展示全文或录音播放器。
- **练习详情**：顶部返回与紧凑步骤进度；中间显示当前步骤；一个主要按钮。题目随时可展开查看。范文和句型按需展开。
- **文章组织**：三个简短输入区起步，具体例和总结按级别开放；生成预览只是忠实拼接所写内容，不自动替用户添加理由。
- **录音步骤**：突出开始／停止和时间；结束后显示试听与保存，再录作为次要操作。
- **结果页**：本次表达、一个改进目标、再次表达按钮；两次录音轮流播放，避免默认同时播放。
- **历史**：保存每次练习的题目版本、草稿版本、提示程度、录音模式、录音、反馈、自查和练习时间。旧记录使用当时版本，避免题目更新改变历史意义。

移动端单栏，主要操作靠近拇指区域，但不能遮住输入框或播放器；键盘打开时保留输入内容与保存入口。计时变化不能反复打断读屏。播放与录音状态用文字配合图标表达。

统计记录「练习次数、完成阶段、表达时长、使用提示程度、待加强项目」，不并入选择题正确率。「表达完成」「模仿完成」「反馈待处理」分别记录；只写作也可完成写作模式，不冒充已完成口语任务。

2026-09-09静态代码检查结果，尚未进行浏览器或设备验证：

- `src/features/practice/MixedPracticeHub.tsx` 的分项学习目前包含词汇、语法、听力、阅读，可添加入口。
- `src/types.ts` 中已有选择式听力题与录音类型；意见表达需要独立类型，不能硬塞 `choices` 或 `answerIndex`。
- `src/features/listening/ListeningPanel.tsx` 已有麦克风录制、试听、上传、变速播放与反馈展示，可提取公共组件；现有播放器不是完整的 shadowing 练习流程。
- `server/storage.mjs` 已有按用户保存录音文件、SQLite元数据与分析结果的模式；意见表达应使用独立关联或通用练习录音模型，不创建伪听力题。
- `server/api.mjs`、`server/mcp-server.mjs` 已有「保存录音→Agent获取上下文→回写分析」链路。静态代码不能证明当前音频分析实际可用，第一版必须保留完整的手动回听与自查路径。
- `docs/ui-design-guidelines.md` 要求单页单职责、列表与详情分离、渐进展开，继续沿用。

建议数据概念：

| 对象 | 必需信息 |
| --- | --- |
| OpinionQuestion | id、版本、标题、场景、子类型、对方观点（条件必填）、任务、允许立场、要求、提示、范文、来源、审核状态 |
| OpinionModel | id、版本、对应立场、按功能标注的段落、音频引用、经核验的片段时间 |
| OpinionAttempt | id、用户、题目与版本、练习路径、阶段、提纲、草稿版本、提示程度、自查、开始／完成时间 |
| PracticeRecording | id、用户、attemptId、模式（表达／逐句跟读／shadowing）、轮次、时长、音频引用、modelId与版本（模仿时）、语速、片段、保存时间 |
| OpinionFeedback | attemptId／recordingId、来源（自查／Agent）、文本或音频证据、各项反馈、下一步、分析状态 |

题目状态：草稿 → 已审核 → 可练习 → 归档。音频是否可用单独记录，文本题可以先可练习。

录音保存和分析状态分离：上传中／已保存／上传失败；未请求分析／待处理／处理中／已完成／失败。分析失败可重试，不影响已保存录音和练习完成状态。

题目与产品设计可在仓库中维护；学习者草稿、录音与反馈属于个人学习数据，使用当前本地应用数据存储，不能写入Git。跨项目的学习笔记仍使用知识库目录。音频读取、删除与反馈查询均按当前用户隔离；前端不暴露服务器文件路径。

## 10. 第一版范围与验收

第一版同时覆盖组织文章、自主录音和基础 shadowing，而不是只有一个新题型标签：

1. 按用户指定的五个教材主题准备审核后的改编题，每题提供三种任务和两种立场的原创示范。正式自主表达统一约2分钟；现有短口语文本用于局部跟读，完整示范需按2分钟结构扩写并在录音后实测调整。先以电车主题验证三种任务及两份完整示范音频，再补齐其余主题；无音频题明确显示状态。长文为400—500字写作档，字数不能直接证明口语时长。
2. 关键词提纲、短文草稿、按功能分段的参考表达；首次作答默认隐藏范文。
3. 录音、试听、再录、保存、下载、删除；首次与第二次表达可分别回听。
4. 整段与预切片段播放、重播、语速、隐藏文本；逐句跟读与 shadowing 有不同播放行为。
5. 自查、改进目标、保存练习记录；复用Agent反馈模式时必须验证实际链路。
6. 表达入口、详情、结果和历史在桌面与手机可操作。

后续再考虑自动转写、个性化修订稿配音、实时对话、自由A—B循环、精细音频对齐。它们不阻塞第一版的独立练习。

验收必须覆盖：

- 从当前实际运行网站进入题目，完成「提纲→首次录音→回听→跟读→再次表达→记录」，刷新后仍能读取已保存内容。
- 赞成、反对都能完成；自由观点与范文不同不会被判错；直接表达题不被要求回应不存在的对方。
- 写作与口语记录可区分；纯跟读不冒充独立表达；新手示范后作答的提示条件可追溯。
- 麦克风拒绝、停止、切题、离开、上传失败与恢复路径不丢失已保存数据，不残留录音状态；未保存内容有明确保护。
- shadowing 可连续播放，逐句跟读可在片段后暂停；选定片段、范文、文本与录音关联正确。
- 无音频、无分析服务、无转写时依然可以练习，界面不会展示伪造的分析结果。
- 在目标桌面浏览器和手机浏览器实际验证录制、编码格式、保存和回放；构建通过与真实设备录音成功分开报告。
- 原听力练习与录音继续可用，已有用户数据不迁移丢失，新的表达练习不改变官方题型和模拟考试计分。
