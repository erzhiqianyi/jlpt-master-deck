# 云端朗读持久缓存

## 存储与默认策略

Web `/api/tts/speak` 在认证、凭据检查后查缓存。Cloudflare 复用现有 `MEDIA` R2，专属对象前缀 `tts-cache/v1/`；Durable Object SQLite 只存 key、用户、对象路径、MIME、字节数、创建/访问时间和状态，不保存原文、凭据或 base64 音频。Node 采用同样元数据表，二进制在数据库目录旁的 `tts-cache` 目录（可用 `JLPT_TTS_CACHE_PATH` 设置）。目录和 SQLite 必须放在持久卷并保留现有 TTS 主密钥。

默认 30 天闲置期限、180 天绝对期限、每用户 200 MiB、2,000 段，按最近访问优先保留。期限均从后台请求计时；本地播放速度不改变声音字节，不进入 key。每段最多 500 字，实际 Web 分段最多 450 字。以 30–90 秒、48–128 kbps 假设，每段约 0.18–1.44 MB，200 MiB 约 145–1,160 段；这是容量估算，实际服务商编码、语速和文本长度会改变结果。

Node 环境变量 / Cloudflare Worker vars（同名）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| TTS_CACHE_ENABLED | true | 设 false 跳过读写；已有对象仍可维护清理 |
| TTS_CACHE_IDLE_DAYS | 30 | 最后访问后闲置期限 |
| TTS_CACHE_MAX_DAYS | 180 | 创建后绝对期限 |
| TTS_CACHE_MAX_BYTES | 209715200 | 每用户音频字节上限 |
| TTS_CACHE_MAX_ENTRIES | 2000 | 每用户条数上限 |

数字须为正有限数，否则使用默认值。写入前预留容量，失败删除的 tombstone 仍计入容量；无法腾出空间时只返回即时合成，不继续新增对象。外层事务回滚产生的无元数据孤儿对象不在该上限内，需要下述生命周期兜底。单个音频超过容量直接返回、不缓存。

## 隔离、失效和并发

HMAC-SHA256 使用现有 TTS 主密钥，输入包括用户 ID、修剪首尾空白后的原文、provider、默认音色归一化后的 voice、style、role、凭据（含 region）、随机加密凭据代次、模型、输出格式、实现版本。不会折叠内部空白或做 Unicode 归一化，以免改变朗读。对象名与日志不含原文或凭据。修改 provider 模型、API 版本、编码、SSML 或其他影响输出的实现时，必须同步更新 `server/tts/index.mjs` 中 identity/version；目前模型和格式是服务端固定值，没有客户端自定义参数。

保存凭据（即使值相同）、删除后重建均开启新代次，旧对象不再命中，按正常期限/容量回收。每次请求都需应用认证及当前可解密凭据；等待期间和合成完成后再检查代次。命中不会向服务商验证其账户是否已被外部撤销，因此不能实时获知服务商控制台撤销；应用内删除凭据可立即阻止之后的命中。

Node 单进程按用户串行处理，成功写入后并发相同请求只合成一次；不同用户并行。Cloudflare 沿用现有单数据库 Durable Object 的请求并发门。**多个 Node 进程共享同一 SQLite/目录尚不支持跨进程合成去重**，应运行一个后端进程。缓存存储故障回退到即时合成，故障期间可能再次计费；生成失败不保存。

响应仍为 `private, no-store`，避免 HTTP 代理/浏览器持久存储私人语音。没有新增公开 R2 URL。上传听力、录音、图片和 iOS AVSpeechSynthesizer 均不受影响。

## 清理与部署

请求时按相同 20 次删除/5 秒预算清理当前用户闲置/过期/超限条目，命中时独立检查期限，写入前腾出容量。预算检查在对象操作之间执行，单次 R2 操作延迟仍受平台限制。删除前将条目标记不可用，删除失败保留元数据并退避一小时（维护任务下次运行时重试），让后续用户继续清理；待完成上传也记录元数据。对象操作严格验证专属前缀及十六进制名称，不能清理 `listening-audio/`、`listening-recordings/` 等原始媒体。

Cloudflare 成功请求后在没有现有 alarm 时安排一天后的 Durable Object alarm；alarm 每轮最多尝试删除 20 个对象、5 秒预算，预算耗尽一分钟后续跑，完成后每日调度，保留现有媒体删除重试机制。不需要新增 Cron、bucket、绑定或权限。首次成功请求后才开始日常任务。闲置过期在下次请求/每日任务执行时物理删除，并非精确到秒。

Node 无驻留任务：部署时用现有调度器每日执行 `node scripts/cleanup-tts-cache.mjs`，使用与服务相同的环境和工作目录。维护命令须在 Node 服务停止时执行，避免独立进程与上传竞争。没有调度器时仍会在当前用户请求时清理，但永不回访用户的文件不会自动删除。

表为增量 `CREATE TABLE IF NOT EXISTS`，Node 首次使用时创建，Cloudflare 构造时创建；无数据回填、无原始音频迁移。无需更新旧初始 schema 快照。部署前先备份数据库；回滚代码不会删除现有缓存，可以保留等待再次启用。

R2 写入与外层 Durable Object SQL 事务不能原子提交：若 R2 上传成功但外层事务回滚，极少数对象可能没有元数据，普通清理无法发现。建议部署时由管理员另设 **仅限 `tts-cache/v1/` 前缀** 的 R2 绝对生命周期上限，例如 181 天（默认绝对期限 180 天的保护网）。不要设置整个 bucket 的规则；若调整绝对期限，相应调整生命周期。生命周期不是 LRU，不能代替代码里的闲置清理。此任务未创建或修改任何生命周期配置，也未执行生产删除。

## 成本与验证范围

命中省去服务商合成，但有一次 R2 读取及 SQLite 元数据更新；miss 有对象写入，过期有删除和元数据维护。每个活跃用户最多约 0.195 GiB 正常音频存储，1,000 个满额用户约 195 GiB，不含短暂超限、孤儿对象和原始媒体。频繁极短段会先触发 2,000 条上限。没有承诺免费额度或金额，实际账单依账户合同、R2 操作次数、区域及 TTS 服务商定价计算。线上命中率和故障回退频率尚未测量。

自动测试使用 mock provider、临时本地 SQLite/文件和 Miniflare R2；不调用任何付费 TTS。真实 Azure/OpenAI/Google、生产 R2 权限/费用及长期 alarm 调度需部署后验证。

## 绝对期限与授权

180 天绝对期限是可配置的保守起点，用于避免常用但已过时的服务商声音无限续期，并给孤儿对象生命周期提供一致的有限上限。它不是服务商强制期限；满期下一次请求将重新合成，可能计费。30 天闲置期限仍是主要回收机制。

不新增 secrets：HMAC 复用已有 `TTS_SECRETS_KEY`（Cloudflare）/ `JLPT_TTS_SECRETS_KEY` 或已有本地持久 key 文件（Node）。不调用新的 OAuth 或账户授权流程；沿用现有 R2 MEDIA 绑定和 TTS 凭据。若旧部署本身未配置 TTS 主密钥，其原有 TTS 功能已不可用，本改动不自动创建云 secret。
